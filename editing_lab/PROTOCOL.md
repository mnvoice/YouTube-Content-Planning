# 편집 사례 한 건의 진행 순서

역할 지시문: `roles/` (공통 규칙 + 검토자 3 + 진행자). 논문 기준: `criteria/`.
이 문서는 후속 지시를 받은 뒤 사례 한 건을 진행할 때 따른다. 준비 단계(2026-09-30)에서는 사례를 진행하지 않았다.

## 0. 시작 전 (진행자)

- 이전 판단 기록을 **실제로 읽는다**: `judgments.jsonl`, `cases/` 아래 관련 사례. 읽은 파일 경로와 SHA-256을 사례 작업 기록에 남긴다.
- 파일이 아직 없으면 "기록 없음"으로 남긴다.

## 1. 원문 고정 (진행자)

원문, 필수 사실 목록, 작성 목적 한 문장, 이번 사례에서 허용할 변경 종류 **하나**, 반복 한도(조정 1회),
필수 사실의 실제 순서 기준(시간 순서 또는 논리적 선후)을 적는다.

## 2. 독립 검토 (검토자 3, 서로의 의견 없이)

각 검토자에게 1단계에서 고정한 것만 준다. 각자 최소 변경안 **하나**를 필수 형식 8항목으로 낸다.

## 3. 상호 검토 (검토자 3)

세 제안을 모두 전달한다. 각 검토자는 다른 두 제안에 구체적인 반론이나 보완을 낸다 (대상 구절 + 근거).

## 4. 조정 (검토자 3, 한 번만)

필요하면 자기 제안을 한 번만 고친다. 새로운 근거 없이 합의를 반복하지 않는다. 합의되지 않은 의견은 남긴다.

## 5. 진행자 정리

- 제안이 '대상 구절 + 수정 행동'을 갖췄는지 확인하고, 채택안을 원문에 적용한 뒤 글자 단위로 대조한다.
- 제시 순서: **원문 → 변경안 → 변경점 → 수정 이유 → 예상 차이와 반례**.
- 여러 변경을 결합한 문단 개선은 이 단계에서 하지 않는다. 필요하면 별도 단계로 제안만 한다.

## 6. 사용자 반응 기록

- 사용자가 느낀 자연스러움, 이해, 분위기 변화와 **그 이유**를 사용자 표현 그대로 보존한다.
- 모델 예상, 사용자 반응, 더 넓은 독자 평가를 다른 칸에 둔다. 기존 독자 지표의 `null`은 그대로 둔다.

## 7. 판단 갱신

- 반응이 들어오면 세 관점의 예상과 대조한다: 맞은 점, 틀린 점, 틀린 이유.
- 다음 글에 적용할 조건을 `judgments.jsonl`에 한 줄 추가한다. 기존 줄은 고치지 않고, 바뀐 판단은 새 줄로 쌓는다 (`supersedes`로 이전 줄 id를 가리킨다).
- 이것은 기록을 활용하는 것이며 모델 가중치 재훈련이 아니다.

## 협의를 여는 때

새 편집 사례를 다룰 때, 새로운 사용자 반응이 들어왔을 때만. 예약 실행이나 백그라운드 작업은 만들지 않는다.

## 파일 규칙

| 파일 | 내용 | 규칙 |
|---|---|---|
| `cases/<사례id>.md` | 원문, 제안자, 독립 검토, 상호 검토, 조정, 최종 결정, 사용자 반응, 재사용 조건 | 사례마다 새 파일. 양식: `templates/case_template.md` |
| `cases/<사례id>.jsonl` | 그 사례의 작업 기록 (한 줄 = 한 행동) | 저장 후 다시 읽어 줄 수·SHA-256 검증 |
| `judgments.jsonl` | 다음 편집에 적용할 조건 | 덧붙이기만. 고치지 않음 |
| `logs/*.jsonl` | 준비·운영 작업 기록 | 덧붙이기만 |

사례 id 예: `CASE-20261001-001`.

### 작업 기록 한 줄의 칸 (JSONL)

`ts` (UTC), `case_id`, `step` (0~7), `actor` (moderator / reviewer_1 / reviewer_2 / reviewer_3 / user),
`action`, `target`, `result` (ok / blocked / partial), `detail`, `sha256` (파일을 읽거나 쓴 경우).

### 판단 기록 한 줄의 칸 (JSONL)

`id`, `ts`, `from_case`, `condition` (언제 적용하나), `judgment` (무엇을 하나 / 하지 않나), `perspective` (어느 관점),
`evidence_level` (논문 직접 / 응용 판단 / 미검증 예상 / 사용자 반응 1건), `model_expectation`, `user_reaction`,
`mismatch_reason`, `reader_metrics` (기존 값 그대로, 없으면 `null`), `supersedes`.
