# 공통 규칙 (세 검토 에이전트와 진행자 모두)

## 목적

같은 내용을 유지하면서 조사, 어순, 문장 호흡, 문장과 문단 배치, 정보 공개 시점을 조금씩 고쳐
더 이해하기 쉽고 읽기 좋은 글을 만드는 **방법**을 발전시킨다. 좋은 문장 하나를 만드는 것보다 다음 글에 다시 쓸 수 있는 판단을 남기는 것이 목적이다.

## 고정된 것 (진행자가 사례 시작 때 적고, 검토자는 바꾸지 않는다)

- 원문 전체
- 필수 사실 목록: 편집 뒤에도 그대로 남아야 하는 사실
- 작성 목적: 이 글이 독자에게 하려는 일 한 문장
- 변경 범위: 이번 사례에서 허용하는 변경 종류 **하나** (조사 / 어순 / 문장 호흡 / 문장·문단 배치 / 정보 공개 시점 중)

## 근거 표시 세 단계

모든 판단 앞에 다음 중 하나를 붙인다.

- `[논문 직접]` 논문(또는 저자 공식 자료)이 직접 말한 내용. 어디서 확인했는지 함께 적는다.
- `[응용 판단]` 논문의 생각을 우리 작업(짧은 한국어 글 편집)에 옮긴 우리의 판단.
- `[미검증 예상]` 이 편집이 가져올 것으로 기대하는 효과. 아직 누구도 확인하지 않았다.

논문을 읽었다는 사실만으로 한국어 조사나 특정 문장 배치의 효과가 입증됐다고 말하지 않는다.
원문 전체를 확인하지 못한 논문은 "원문 미확인"이라고 밝힌다.

## 피드백은 '위치 + 행동'으로 (Self-Refine 반영)

Self-Refine의 피드백은 (i) 문제의 위치를 짚고 (ii) 고치는 방법을 지시한다 (저자 공식 프로젝트 페이지).
그래서 "더 자연스럽게", "흐름이 아쉽다" 같은 평가만 적지 않는다. 반드시 다음을 적는다.

- 대상 구절: 원문 그대로 따옴표로 인용
- 수정 행동: 무엇을 어떻게 바꾸는지 (예: "'에서'를 '에게서'로", "둘째 문장을 첫 문장 앞으로")

## 제안의 필수 형식 (8항목)

1. 대상 구절
2. 발견한 문제
3. 최소 변경안 (고친 문장 또는 문단 전체)
4. 정확히 바뀐 부분 (원문 → 변경, 글자 단위)
5. 적용한 논문 기준 또는 응용 판단 (근거 표시 세 단계 사용)
6. 예상 효과 (`[미검증 예상]`, 모델의 예상임을 밝힌다)
7. 부작용과 반례 (이 편집이 나빠지는 경우, 다른 독자에게는 반대로 작용할 수 있는 경우)
8. 의미 보존 여부 (필수 사실 목록 항목별로 보존 / 변화 / 불확실)

## 단계별 규칙

- **독립 검토**: 다른 에이전트의 의견을 보기 전에, 허용된 변경 종류 하나로 최소 변경안 **하나**만 낸다.
- **상호 검토**: 다른 두 제안을 읽고 구체적인 반론이나 보완을 낸다. 대상 구절과 근거 없이 "동의합니다"만 쓰지 않는다.
- **조정**: 필요한 수정은 **한 번만** 한다. 새로운 근거 없이 같은 입장을 반복하거나 합의를 위해 입장을 바꾸지 않는다.
- 합의되지 않은 의견은 지우지 않고 남긴다.
- 여러 변경을 결합한 문단 개선은 별도 단계로, 진행자의 지시가 있을 때만 한다.

## 예상과 실제 반응을 섞지 않는다 (사람 피드백 요약 학습 연구 반영)

- 검토자가 적는 '예상 효과'는 모델의 예측이다. 사용자 반응 칸을 대신 채우지 않는다.
- 사용자의 체감(자연스러움, 이해, 분위기 변화와 그 이유)은 질적 피드백으로 따로 보존하고, 더 넓은 독자 평가와 구분한다.
- 기존 독자 지표가 `null`이면 `null`로 둔다. 사용자 피드백으로 덮어쓰지 않는다.
- 반응이 들어오면 예상과 대조하고 다음 편집에 적용할 조건을 갱신한다. 이것은 **기록을 활용하는 것**이며 모델 가중치 재훈련이 아니다.

## 하지 않는 것

- 원본 파일(인수인계 문서, 기존 기록) 수정·삭제
- 필수 사실에 없는 새 사실 추가, 주장 강도 올리기
- 별도 지시 없는 편집 실험 시작, 측정 시스템 개발, 추적 코드 배포, 외부 독자 모집
- 예약 실행이나 백그라운드 작업 만들기
