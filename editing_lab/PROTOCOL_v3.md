# 토론과 피드백 절차 3판

2판(`PROTOCOL.md`)은 보존한다. 역할 지시문: `roles/v3/`. 실행 전 읽기 목록: `NEXT_RUN.md`.
이 문서는 후속 지시를 받은 뒤 사례 한 건을 진행할 때 따른다. 2026-09-30 현재 편집 사례는 진행하지 않았다.

## 사례 한 건의 순서

| 단계 | 누가 | 하는 일 | 남기는 것 |
|---|---|---|---|
| 0. 실행 전 읽기 | 진행자 | `NEXT_RUN.md` 목록을 실제로 읽고 SHA-256 대조 | 읽은 파일·지문 (작업 기록) |
| 1. 원문 고정 | 진행자 | 원문·출처, 필수 사실, 작성 목적, 변경 종류 하나, 실제 순서 기준, 알려진 함께 달라지는 요인, 조정 1회 한도 | `source_ref`, `fixed_facts`, `writing_goal`, `operator`, `confounds` |
| 2. 독립 검토 | 검토자 3 (서로 보지 않음) | 수정안 하나(8항목) 또는 반론 또는 유지 의견. 관찰 메모 | `agent_proposal` |
| 3. 상호 검토 | 검토자 3 | 다른 두 검토에 구체적인 반론·보완 (대상 + 근거) | 상호 검토 표 |
| 4. 조정 | 검토자 3 | 한 번만. 합의되지 않은 의견 보존 | 조정 표 |
| 5. 진행자 정리 | 진행자 | 채택안 적용, 글자 단위 대조, 원문 → 변경안 → 변경점 → 수정 이유 → 예상 차이와 반례 | `before`, `after`, `diff`, `editorial_decision`, `expected_effect`, `counterexample`, `meaning_check` |
| 6. 사용자 반응 | 사용자 → 진행자 | 선택(A / B / 차이 없음 / 판단 어려움)과 그 대목, 다섯 질문, 읽은 순서 | `user_feedback` |
| 7. 판단 갱신 | 진행자 | 예상과 반응 대조, 틀린 이유, 재사용 조건과 다음 비교 | `application_conditions`, `next_test`, `judgments.jsonl` |

## 사용자 반응의 다섯 질문 (점수 합계로 순위를 만들지 않는다)

- 이해: 한 번 읽고 누가 무엇을 했는지 설명할 수 있는가? 다시 읽어야 한 구절은?
- 자연스러움: 어느 표현에서 딱딱함이나 어색함을 느꼈는가? 변경 뒤 어디가 나아지거나 나빠졌는가?
- 읽고 싶은 힘: 다음 문장으로 넘어가게 한 곳은? 그것이 궁금증인지 혼란인지 구분되는가?
- 분위기와 여운: 따뜻함, 긴장, 거리감, 과장감, 훈계하는 느낌 중 무엇이 달라졌는가?
- 의미 보존: 새로 믿게 된 근거 없는 내용이 있는가?

짧은 선택과 한 구절의 이유만으로도 기록할 수 있다. 사용자 체감은 질적 피드백이며, 더 넓은 독자 평가와 구분한다.
기존 독자 지표의 `null`은 덮어쓰지 않는다.

## 세 단계 (서로 같은 증거로 취급하지 않음)

1. **문장 하나의 작은 변경**: 변경 종류 하나씩 따로 원문 옆에 둔다. 211자 배치 사례(초고 대 B)를 출발 자료로 쓸 수 있다.
2. **한 문단에서 결합**: 단일 비교 뒤에 조합안을 만들고 무엇을 합쳤는지 기록한다. 실패 사례도 보존한다.
3. **새 소재로 옮기기**: 이전 결과문을 복사하지 않고 편집 판단을 적용한다. 판단 사례를 준 조건과 주지 않은 조건을 비교할 수 있으며, 생성 횟수와 자료량 차이를 기록한다.

후속 비교 조건: 단일 에이전트의 일반 수정과 구체적 자기 피드백. 같은 초고, 수정 기회, 비용을 맞춘다.

## 기록 필드 (인수인계서 v2의 필드 이름을 따름)

| 필드 | 담을 내용 |
|---|---|
| `case_id`, `source_ref` | 사례와 원문 위치 |
| `fixed_facts`, `writing_goal` | 보존할 사실과 글의 목적 |
| `operator`, `target_span` | 변경 종류와 정확한 구절 |
| `before`, `after`, `diff` | 전후 문장과 실제 변경 |
| `agent_proposal`, `editorial_decision` | 누가 무엇을 제안했고(수정안/반론/유지) 무엇을 적용했는지 |
| `expected_effect`, `counterexample` | 모델의 예상 효과와 반례 |
| `user_feedback`, `reader_observation` | 사용자 질적 반응과 별도 독자 관측 (없으면 `null`) |
| `meaning_check`, `confounds` | 의미 변화 검사와 함께 달라진 요인 |
| `application_conditions`, `next_test` | 언제 재사용할지와 다음 비교 |

## 파일 규칙

| 파일 | 내용 | 규칙 |
|---|---|---|
| `cases/<사례id>.md` | 위 필드를 사람이 읽는 형태로 | 사례마다 새 파일. 양식: `templates/case_template_v3.md` |
| `cases/<사례id>.jsonl` | 그 사례의 작업 기록 (한 줄 = 한 행동) | 저장 후 다시 읽어 줄 수·SHA-256 검증 |
| `judgments.jsonl` | 재사용 조건 | 덧붙이기만. 바뀐 판단은 새 줄로 쓰고 `supersedes`로 이전 줄을 가리킴 |
| `logs/*.jsonl` | 준비·운영 작업 기록 | 덧붙이기만 |
