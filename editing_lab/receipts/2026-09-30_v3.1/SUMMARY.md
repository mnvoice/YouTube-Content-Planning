# 3.1판 수신 확인 요약 (진행자 작성, 2026-09-30)

보고 원문: `reviewer_1.md`, `reviewer_2.md`, `reviewer_3.md` (받은 그대로).
전달 방식: 새 에이전트를 만들지 않고 준비 단계의 세 에이전트에게 메시지로 저장소 경로를 보냈다. 실행 환경이 비동기로 재개했고 예약 작업은 없다.
세 에이전트와 진행자는 같은 기반 모델이다. 아래 대조는 진행자가 한 것이며 사람의 확인이 아니다.

## 1. 자료 읽기

| 에이전트 | 읽은 파일 (7개 요청) | 보고한 SHA-256 | 목록 밖 |
|---|---|---|---|
| 1 | 7개 모두 전체 | 7개 모두 저장소 파일과 일치 | 자기 3판 기준 카드와 SOURCES.md는 있는지만 확인 |
| 2 | 7개 모두 전체 | 7개 모두 일치 | 3.1판 문장 단위 규칙을 Python으로 적용해 초고·B 모두 12단위, B = 3–12 + 1–2 확인 |
| 3 | 7개 모두 전체 | 7개 모두 일치 | 없음 |

- 보낸 뒤 3.1판 파일이 바뀌지 않았다 (보낼 때 기록한 SHA-256과 같음).
- 인수인계서와 `variants.json`의 해시는 3판 수신 확인 때와 같다.
- 추가 기존 검토 자료(기존 토론 보고서 `report.md`, 기존 논문 검토 자료 등)는 사용자에게서 전달되지 않았다. 세 에이전트 모두 "받지 못함"으로 적었고 내용을 추측하지 않았다.

## 2. 역할 이해 (지시문과 대조)

| 에이전트 | 보고한 핵심 | 대조 |
|---|---|---|
| 1 | 목적을 "독자가 알게 되거나 하게 될 한 가지"로 다시 적고 하위 목표로 나눔. 주 담당은 조사, 어순(문장 안), 문장 호흡, 강조와 종결(문장 안). 목적 판단과 표현 판단의 근거 표시를 나눔 | 맞음 |
| 2 | 두 순서 표(실제 순서, 접하는 순서의 첫 암시·첫 명시). 위치만 바꾸는 수정안. "원래 자리 아님"을 나빠짐으로 판정하지 않음 | 맞음 |
| 3 | 네 차원 따로, 9항목 판정표를 수정안·유지·반론 모두에. 관문은 거부권이 아님. 결함이 있을 때만 수정안 | 맞음 |

세 에이전트 모두 논문 기준을 "저자 공식 자료 / 원문 미확인(2차) / 응용 판단 / 한국어 표현 응용 판단"으로 나눠 보고했다.
Flower–Hayes에는 저자 공식 자료도 없어 검색 요약만 근거라는 점(에이전트 1), DOC는 README와 코드만 읽었다는 점(에이전트 2), SummEval은 본문과 쪽수가 미확인이라는 점(에이전트 3)을 각자 밝혔다.

## 3. 에이전트 1의 지적: Q1·Q3·Q7·Q12의 지위

3.1판 규칙에 넣은 Q1(211자 사례의 변경 종류 기본값), Q3(12단위 문장 규칙), Q7(관문은 거부권 아님), Q12(한국어 표현 판단의 근거 자료 기본값)는
**사용자가 확인한 결정이 아니라 진행자가 넣은 기본값**이다. 사용자 확인 전까지 이 네 가지는 "진행자 기본값"으로 기록한다.

## 4. 새 질문 (첫 사례 전 진행자가 정할 운영 세부) — 3.1판에는 반영하지 않음

3.1판을 지금 고치면 이번 수신 증거가 깨지므로, 아래는 첫 사례의 범위 고정 때 사례 기록에 적어 적용한다.

| # | 질문 | 진행자 처리안 |
|---|---|---|
| R1-2 | "목적에 맞지 않는 종결"이 끝 문장의 위치 문제이면? | 강조와 종결 사례에서는 관찰 메모로. 배치 사례에서는 목적 관점의 배치 수정안이나 유지·반론으로 낼 수 있다 |
| R1-3 | 3판 기준 카드와 3.1판 지시문의 기준 표가 다르면? | 3.1판 지시문이 우선. 차이는 관찰 메모로 남기고 다음 판에서 정리 |
| R2-1 | 대사를 묶은 번호의 범위 | 대사와 바로 뒤의 발화 동사 문장만 묶는다 (211자 초고는 11단위). 기준 번호는 12단위 |
| R2-2 | 주 담당이 아닌 사례의 독립 단계에서 다른 검토자의 변경을 볼 수 없음 | 독립 단계에서는 "이 구절을 바꾸면 생길 위험"을 유지 의견이나 관찰 메모로 적고, 실제 변경에 대한 반론은 상호 반론 단계에서 |
| R2-3 | 9항목 판정표를 누가 쓰나 | 판정표는 에이전트 3의 의무. 다른 검토자는 필요한 항목만 인용해도 된다 |
| R3-1 | 진행자가 고른 최종 문자열이 에이전트 3이 판정한 문자열과 다르면? | 한 글자라도 다르면 사용자에게 보이기 전에 에이전트 3의 9항목 검사를 다시 받는다. `meaning_check`는 에이전트 3의 판정으로 채운다 |
| R3-2 | 초고 대 B처럼 미리 만든 후보가 입력일 때 | B는 "기존 후보"로서 1단계 고정 내용에 포함한다. 독립 검토에서 세 검토자 모두 B를 판정해도 된다 (다른 검토자의 제안이 아님) |
| R3-3 | 유지 의견의 9항목 판정표는 무엇을 비교하나 | 원문 대 "고치면 생길 위험"에 적은 가상 변경. 가상 변경을 적지 않았으면 판정표를 생략하고 그 사실을 적는다 |
| R1-1 | Q1·Q3·Q7·Q12의 지위 | 3절 참고. 사용자 확인을 받는다 |
