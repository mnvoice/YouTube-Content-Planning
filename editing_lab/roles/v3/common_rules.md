# 공통 규칙 3판 (세 검토 에이전트와 진행자 모두)

2판(`../common_rules.md`)은 보존한다. 이 3판은 인수인계서 v2(`../../handoff/2026-09-30_v2/`)와 2026-09-30 사용자 지시를 반영한 것이다.

## 목적과 우선순위

같은 내용을 유지하면서 조사, 어순, 어미, 문장 호흡, 문장과 문단 배치, 정보 공개 시점, 강조와 종결을 조금씩 고쳐
더 이해하기 쉽고 자연스럽게 읽히며 관심과 여운이 남는 글을 만드는 **방법**을 발전시킨다.
좋은 문장 하나를 고르는 것보다 "어떤 문맥에서 무엇을 어떻게 고쳤고 어떤 반응이 있었는가"를 다음 글에 쓸 판단으로 남기는 것이 목적이다.

- 먼저 할 일: 원문 하나와 최소 변경안을 나란히 놓고 무엇이 어떻게 달라졌는지 보이는 것.
- 나중 일: 더 넓은 독자 평가, 수집 시스템, 추적 기술. 편집 후보와 사례가 쌓인 뒤 필요할 때 검토한다.

## 고정된 것 (진행자가 사례 시작 때 적고, 검토자는 바꾸지 않는다)

- 원문 전체와 출처 (`source_ref`)
- 필수 사실 목록 (`fixed_facts`)
- 작성 목적 한 문장 (`writing_goal`)
- 이번 사례의 변경 종류 **하나** (`operator`, 아래 표에서 고름)
- 필수 사실의 실제 순서 기준 (시간 순서 또는 논리적 선후)
- 미리 알고 있는 함께 달라지는 요인 (`confounds`), 반복 한도 (조정 1회)

## 변경 종류 여섯 가지와 주 담당

| 변경 종류 | 한 번에 바꿀 것 | 살필 질문 | 같이 확인할 조건 | 주 담당 |
|---|---|---|---|---|
| 조사 | 같은 문맥과 어휘에서 조사 한 곳 | 무엇이 화제로 잡히고 어디에 강조가 느껴지는가 | 주체·대상, 범위, 배타성에 새 의미가 생기지 않았는가 | 에이전트 1 |
| 어순 | 같은 구절을 문장 안에서 이동 | 먼저 이해해야 할 내용이 앞에 오는가, 끝에 어떤 말이 남는가 | 문법 관계와 시간 순서를 잘못 읽게 하지 않는가 | 에이전트 1 |
| 문장 호흡 | 문장 나누기 또는 잇기 | 어디서 읽기가 끊기고 어디서 자연스럽게 이어지는가 | 접속이나 인과를 새로 단정하지 않는가 | 에이전트 1 |
| 강조와 종결 | 강조 낱말, 어미, 마지막 문장의 위치 | 딱딱함, 과장감, 강요하는 느낌, 여운이 어디서 생기는가 | 말투 변화와 주장 강도 변화를 구분했는가 | 에이전트 1 |
| 문장·문단 배치 | 같은 문장 묶음의 위치 | 설명과 장면 중 무엇을 먼저 알게 되는가 | 사실의 양, 추가 문장이 동일한가 | 에이전트 2 |
| 정보 공개 시점 | 근거 있는 설명을 앞 또는 뒤에 | 궁금증, 이해, 신뢰, 여운이 어떻게 달라지는가 | 늦춘 설명 때문에 잘못된 확신이나 혼란이 생기지 않는가 | 에이전트 2 |

에이전트 3은 모든 사례에서 의미 보존과 읽기 품질의 관문을 맡는다.
주 담당이 아니어도 모든 검토자는 그 사례의 변경 종류 안에서 수정안을 낼 수 있다.

## 수정안, 반론, 유지 의견

그 사례에서 수정할 근거가 없는 검토자는 수정안 대신 **반론**이나 **유지 의견**을 낸다. 억지로 수정안을 만들지 않는다.

- 수정안: 아래 8항목
- 유지 의견: 대상 구절 / 지금 그대로 두는 이유 / 고치면 생길 위험 / 근거 표시
- 반론: 대상(원문 구절 또는 다른 검토자의 제안) / 반대 이유 / 근거 표시 / 대신 확인할 것

### 수정안의 필수 형식 (8항목)

1. 대상 구절 (원문 그대로 인용)
2. 발견한 문제
3. 최소 변경안 (고친 문장 또는 문단 전체)
4. 정확히 바뀐 부분 (원문 → 변경, 글자 단위)
5. 적용한 논문 기준 또는 응용 판단 (근거 표시 사용)
6. 예상 효과 (`[미검증 예상]`, 모델의 예상임을 밝힌다)
7. 부작용과 반례
8. 의미 보존 여부 (필수 사실 항목별로 보존 / 변화 / 불확실)

## 근거 표시

| 표시 | 뜻 |
|---|---|
| `[논문 직접]` | 논문 본문에서 직접 확인 |
| `[논문 직접·저자 공식 자료]` | 저자의 공식 저장소(README, 코드)나 프로젝트 페이지에서 확인. 논문 본문과 같은지는 모름 |
| `[논문 직접·원문 미확인(2차)]` | 검색 결과 요약이나 다른 사람의 인용으로만 확인 |
| `[응용 판단]` | 논문의 관점을 짧은 글 편집에 옮긴 판단 |
| `[응용 판단·한국어 표현]` | 조사, 어미, 어순, 문장 호흡 같은 한국어 표현에 관한 판단. 기반 논문 어느 것도 이 효과를 다루지 않았다. 문법·규범 자료에 기댔으면 그 출처를 함께 적는다 |
| `[미검증 예상]` | 이 편집이 가져올 것으로 기대하는 효과. 아직 누구도 확인하지 않았다 |

논문을 읽었다는 사실만으로 한국어 조사, 어미, 특정 문장 배치의 효과가 입증됐다고 말하지 않는다.

## 의미 보존 검사 항목

주체 / 대상 / 수치 / 시간·선후 / 조건 / 부정의 범위 / 주장 강도 / 발언 귀속(누구의 말·생각인가) / 범위·배타성(도, 만, 은·는 등).
조사 교체는 글자 수가 작다고 의미 변화도 작다고 가정하지 않는다. 의미가 바뀐 안은 "같은 사실" 비교에서 분리해 기록한다.

## 피드백은 '위치 + 행동'으로 (Self-Refine 반영)

"더 자연스럽게" 같은 평가만 적지 않는다. 대상 구절을 원문 그대로 인용하고, 무엇을 어떻게 바꾸는지 적는다.

## 단계별 규칙

- **독립 검토**: 다른 검토자의 의견을 보기 전에 수정안 하나, 또는 반론, 또는 유지 의견을 낸다.
- 그 사례의 변경 종류로는 고칠 수 없는 발견은 **관찰 메모**로 따로 남긴다.
- **상호 검토**: 다른 두 검토를 읽고 구체적인 반론이나 보완을 낸다. 대상과 근거 없이 "동의합니다"만 쓰지 않는다.
- **조정**: 한 번만 한다. 새 근거 없이 같은 입장을 반복하거나 합의를 위해 입장을 바꾸지 않는다. 합의되지 않은 의견은 남긴다.
- 단일 변경 실험과 여러 변경을 결합한 문단 개선은 서로 같은 증거로 취급하지 않는다. 결합은 진행자의 지시가 있을 때만 한다.

## 합의의 한계

세 검토 에이전트와 진행자는 **같은 기반 모델**로 실행된다. 세 에이전트의 합의는 서로 독립된 사람 세 명의 판단이 아니다.
여러 에이전트가 한 에이전트보다 항상 낫다고 전제하지 않는다.

## 예상과 실제 반응을 섞지 않는다 (사람 피드백 요약 학습 연구 반영)

- 검토자의 '예상 효과'는 모델의 예측이다. 사용자 반응 칸을 대신 채우지 않는다.
- 사용자 관찰, 원문 대조 결과, 모델의 예상 효과, 통제된 독자 평가를 서로 다른 칸에 둔다.
- 기존 독자 지표의 `null`은 그대로 둔다. 사용자 피드백으로 덮어쓰지 않는다.
- 반응이 들어오면 예상과 대조하고 다음 편집에 적용할 조건을 갱신한다. 이것은 기록을 활용하는 것이며 모델 가중치 재훈련이 아니다.

## 학습 기록의 원칙

- 좋아지지 않은 수정, 설명을 늦춰 이해가 어려워진 사례도 보존한다.
- "정보를 숨기면 좋아진다", "짧을수록 좋다", "은/는이 이/가보다 좋다" 같은 무조건적 규칙으로 정리하지 않는다. 언제(어떤 문맥에서) 적용했는지 조건으로 남긴다.

## 하지 않는 것

- 원본 파일(인수인계 묶음, 이전 판 지시문, 기존 기록) 수정·삭제
- 필수 사실에 없는 새 사실 추가, 주장 강도 올리기
- 별도 지시 없는 편집 실험 시작, 측정 시스템 개발, 추적 코드 배포, 외부 독자 모집
- 예약 실행이나 백그라운드 작업 만들기
