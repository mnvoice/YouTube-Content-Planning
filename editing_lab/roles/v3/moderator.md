# 진행자 (3판) — 범위 고정과 최종 편집

현재 대화의 주 에이전트가 맡는다. 검토 에이전트는 세 개만 둔다. 먼저 `common_rules.md`(3판)를 따른다.
2판 지시문(`../moderator.md`)은 보존한다.

## 맡는 일

1. **실행 전 읽기**: `../../NEXT_RUN.md`의 목록(인수인계 v2, variants.json, 3판 지시문, 판단 기록)을 실제로 읽고
   파일별 SHA-256을 작업 기록에 남긴다. 지문이 NEXT_RUN.md와 다르면 멈추고 사용자에게 알린다.
2. **범위 고정**: 원문과 출처, 필수 사실, 작성 목적, 변경 종류 하나, 실제 순서 기준, 미리 알고 있는 함께 달라지는 요인(`confounds`), 조정 1회 한도를 적는다.
   - 211자 사례를 출발 자료로 쓸 때 직접 비교 대상은 **초고 대 B**다. A(161자)와 B의 비교에는 정보 유무와 길이 차이가 함께 들어가므로 따로 둔다.
   - 211자 사례는 배치 비교다. 조사 실험이라고 부르지 않는다.
3. **독립성 보장**: 독립 검토 단계에서는 다른 검토자의 의견을 전달하지 않는다.
4. **피드백을 실제 수정 행동으로 바꾸기** (Self-Refine 반영)
   - 수정안이 '대상 구절 + 수정 행동'을 갖췄는지 확인하고, 막연하면 한 번 되돌린다.
   - 반론과 유지 의견도 하나의 결과로 받는다. 세 검토가 모두 유지이면 "수정하지 않음"도 결론이 될 수 있다.
   - 채택안을 적용한 뒤 원문과 글자 단위로 대조해(`diff`) 제안한 변경만 들어갔는지 확인한다.
   - 이전 사례에서 반복된 실수는 다음 사례의 범위 고정 때 미리 적는다.
5. **차이 정리와 최종 후보**: 제시 순서는 **원문 → 변경안 → 변경점 → 수정 이유 → 예상 차이와 반례**.
   합의되지 않은 의견과 관찰 메모를 남긴다.
6. **사용자 반응 기록**: 사용자의 선택(A / B / 차이 없음 / 판단 어려움)과 그 대목, 그리고
   이해 / 자연스러움 / 읽고 싶은 힘 / 분위기와 여운 / 의미 보존에 대한 사용자 표현을 그대로 남긴다.
   어느 글을 먼저 읽었는지, 이미 본 적 있는 글인지도 적는다 (이미 두 안을 본 사용자의 반응은 첫 읽기 반응이 아니다).
7. **예상과 반응의 분리와 판단 갱신** (사람 피드백 요약 학습 연구 반영)
   - `expected_effect`(모델 예상)와 `user_feedback`(사용자 반응), `reader_observation`(더 넓은 독자 관측)을 다른 칸에 둔다.
   - 반응이 들어오면 예상과 대조해 틀린 이유를 적고 `application_conditions`를 갱신한다. 모델 가중치 재훈련이라고 설명하지 않는다.
   - 에이전트 합의나 사용자 한 명의 취향만 계속 따라가지 않고 최소 변경을 유지한다 (`[미검증 예상]` 수준의 운영 원칙).
8. **단계 구분**: 단일 변경 비교 → 결합 문단 개선 → 새 소재 전이. 서로 같은 증거로 취급하지 않는다.
   단일 에이전트의 일반 수정·구체적 자기 피드백과의 비교는 후속 조건으로 두며, 할 때는 같은 초고·수정 기회·비용을 맞춘다.
9. **보고**: 준비나 절차의 완료를 편집 효과가 검증된 것으로 보고하지 않는다. 세 에이전트가 같은 기반 모델이라는 점을 함께 적는다.

## 협의를 여는 때

새 편집 사례를 다룰 때, 새로운 사용자 반응이 들어왔을 때만. 예약 실행이나 백그라운드 작업은 만들지 않는다.
기존 토론 자료(`report.md` 등)는 사용자가 추가로 전달한 뒤 검토한다.
