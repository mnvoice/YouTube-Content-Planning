# 공통 규칙 3.1판 (세 검토 에이전트와 진행자 모두)

이전 판(1판 복원본, 2판 `../common_rules.md`, 3판 `../v3/common_rules.md`)은 보존한다.
3.1판은 3판에 세 에이전트의 수신 확인 질문(`../../receipts/2026-09-30/SUMMARY.md`의 Q1~Q16) 처리와 2026-09-30 사용자 지시를 반영한 것이다.

## 목적과 우선순위

같은 내용을 유지하면서 조사, 어순, 어미, 문장 호흡, 문장과 문단 배치, 정보 공개 시점, 강조와 종결을 조금씩 고쳐
더 이해하기 쉽고 자연스럽게 읽히며 관심과 여운이 남는 글을 만드는 **방법**을 발전시킨다.
남길 것은 완성문이 아니라 "어떤 문맥에서 무엇을 어떻게 고쳤고, 어떤 반론이 있었고, 사용자 반응으로 판단이 어떻게 달라졌는가"다.

- 먼저 할 일: 원문 하나와 최소 변경안을 나란히 놓고 무엇을 왜 고쳤는지 보이는 것.
- 나중 일: 더 넓은 독자 평가, 수집 시스템, 추적 기술.

## 역할

| 역할 | 맡는 일 | 주 담당 변경 종류 |
|---|---|---|
| 에이전트 1 | 글의 목적과 문장 표현 (조사, 어순, 어미, 문장 호흡) | 조사, 어순, 문장 호흡, 강조와 종결 |
| 에이전트 2 | 문장과 문단 배치, 정보 공개 순서 | 문장·문단 배치, 정보 공개 시점 |
| 에이전트 3 | 의미 보존과 읽기 품질 (모든 사례의 관문) | 없음 (모든 사례에서 검사) |
| 진행자 | 변경 범위 고정, 제안과 반론 정리, 최종 후보 선택 | — |

수정할 근거가 없는 검토자는 수정안 대신 **유지 의견**이나 **반론**을 낸다. 억지로 수정안을 만들지 않는다.

## 고정된 것 (진행자가 사례 시작 때 적고, 검토자는 바꾸지 않는다)

- 원문 전체와 출처 (`source_ref`)
- 필수 사실 목록 (`fixed_facts`)
- 작성 목적 한 문장 (`writing_goal`)
- 이번 사례의 변경 종류 **하나** (`operator`)
- 필수 사실의 실제 순서 기준 (시간 순서 또는 논리적 선후)
- 문장 단위 번호 (아래 '문장 단위' 규칙으로 매김)
- 미리 알고 있는 함께 달라지는 요인 (`confounds`), 반복 한도 (조정 1회)

## 변경 종류 여섯 가지

| 변경 종류 | 한 번에 바꿀 것 | 살필 질문 | 같이 확인할 조건 |
|---|---|---|---|
| 조사 | 같은 문맥과 어휘에서 조사 한 곳 | 무엇이 화제로 잡히고 어디에 강조가 느껴지는가 | 주체·대상, 범위, 배타성에 새 의미가 생기지 않았는가 |
| 어순 | 같은 구절을 **문장 안에서** 이동 | 먼저 이해해야 할 내용이 앞에 오는가, 끝에 어떤 말이 남는가 | 문법 관계와 시간 순서를 잘못 읽게 하지 않는가 |
| 문장 호흡 | 문장 나누기 또는 잇기 | 어디서 읽기가 끊기고 어디서 이어지는가 | 접속이나 인과를 새로 단정하지 않는가 |
| 강조와 종결 | 강조 낱말, 어미, 마지막 문장 **안의** 표현 | 딱딱함, 과장감, 강요, 여운이 어디서 생기는가 | 말투 변화와 주장 강도 변화를 구분했는가 |
| 문장·문단 배치 | 문장이나 문단을 **통째로** 옮김 | 설명과 장면 중 무엇을 먼저 알게 되는가 | 사실의 양, 추가 문장이 동일한가 |
| 정보 공개 시점 | 근거 있는 설명이 처음 드러나는 자리를 앞 또는 뒤로 | 궁금증, 이해, 신뢰, 여운이 어떻게 달라지는가 | 늦춘 설명 때문에 잘못된 확신이나 혼란이 생기지 않는가 |

겹치는 경우의 기본 규칙 (Q1):
- 문장을 통째로 옮기면 기계적으로는 '문장·문단 배치'다. 옮기는 목적이 "이 사실을 언제 알게 할까"이면 '정보 공개 시점'으로 부를 수 있다.
  둘 중 무엇으로 할지는 진행자가 사례 시작 때 하나로 고정하고, 다른 하나의 변화는 `confounds`와 `expected_effect`에 적는다.
- 문장을 옮겨 첫 문장이나 끝 문장이 바뀌는 것은 '강조와 종결'이 아니다. `confounds`에 적는다. '강조와 종결'은 문장 안의 어미·낱말만 다룬다.
- 211자 사례(초고 대 B)의 기본값은 인수인계서의 표현대로 '문장·문단 배치'다. 사례를 시작할 때 사용자가 바꿀 수 있다.

## 문장 단위 (Q3)

기본 규칙: 마침표·물음표·느낌표(닫는 따옴표가 붙으면 그것까지) 뒤의 공백에서 나눈다. 211자 초고는 12단위다.
대사와 뒤따르는 지문("‘뭘 숨겼어?’ 민서가 물었다.")을 한 문장으로 묶은 번호가 필요하면 함께 적되, 기록의 기준 번호는 기본 규칙을 따른다.

## 수정안, 반론, 유지 의견, 관찰 메모

- **수정안** 8항목: 대상 구절(원문 그대로) / 발견한 문제 / 최소 변경안 / 정확히 바뀐 부분(글자 단위) / 근거 표시 / 예상 효과(`[미검증 예상]`) / 부작용과 반례 / 의미 보존 여부(필수 사실별)
- **유지 의견**: 대상 구절 / 그대로 두는 이유 / 고치면 생길 위험 / 근거 표시
- **반론**: 대상 / 반대 이유 / 근거 표시 / 대신 확인할 것
  - 독립 검토 단계의 반론은 **원문 구절만** 대상으로 한다. 다른 검토자의 제안에 대한 반론은 상호 반론 단계부터다 (Q13).
- **관찰 메모**: 그 사례의 변경 종류로는 고칠 수 없는 발견

피드백은 '위치 + 행동'으로 쓴다 (Self-Refine 반영). "더 자연스럽게" 같은 평가만 적지 않는다.

| 표시 | 뜻 |

| `[논문 직접·저자 공식 자료]` | 저자의 공식 저장소(README, 코드)나 프로젝트 페이지에서 확인. 본문과 같은지는 모름 |

| `[미검증 예상]` | 이 편집이 가져올 것으로 기대하는 효과. 아직 누구도 확인하지 않았다 |

- 읽은 범위를 밝힌다: "본문 미확인", "초록만 읽음", "README만 읽음", "코드 일부 읽음" (Q10).
- `[응용 판단·한국어 표현]`에는 매번 근거 자료를 적는다. 기본값은 **"근거 자료: 없음(모델 감각)"**이다.
  문법·규범 자료는 사용자가 지정한 자료만 쓰고, 쓰면 자료 이름과 항목을 적는다 (Q12).
- 논문을 읽었다는 사실만으로 한국어 조사, 어미, 특정 문장 배치의 효과가 입증됐다고 말하지 않는다.

## 의미 보존 검사 9항목

주체 / 대상 / 수치 / 시간·선후 / 조건 / 부정의 범위 / 주장 강도 / 발언 귀속(누구의 말·생각인가) / 범위·배타성(도, 만, 은·는).
조사 교체는 글자 수가 작다고 의미 변화도 작다고 가정하지 않는다.

에이전트 3의 판정은 **거부권이 아니다** (Q7). 9항목 중 하나라도 '변화'로 판정된 안은 "같은 사실" 비교에서 빼고 따로 기록하며,
사용자에게 보여 줄 때는 "의미 변화 있음"을 붙인다. 최종 후보는 진행자가 고른다.

## 흐름 (자세한 것은 `../../PROTOCOL_v3.1.md`)

독립 검토 → 상호 반론 → 조정(한 번) → 진행자 정리 → 사용자 반응에 따른 판단 갱신.
- 독립 검토: 다른 검토자의 의견을 보지 않는다.
- 상호 반론: 대상과 근거 없이 "동의합니다"만 쓰지 않는다.
- 조정: 새 근거 없이 같은 입장을 반복하거나 합의를 위해 입장을 바꾸지 않는다. 합의되지 않은 의견은 남긴다.
- 단일 변경 비교, 결합 문단 개선, 새 소재 전이는 서로 같은 증거로 취급하지 않는다.

## 합의의 한계

세 검토 에이전트와 진행자는 **같은 기반 모델**로 실행된다. 합의는 서로 독립된 사람 세 명의 판단이 아니다.
여러 에이전트가 한 에이전트보다 항상 낫다고 전제하지 않는다.

## 예상과 실제 반응을 섞지 않는다 (사람 피드백 요약 학습 연구 반영)

- 사용자 관찰(`user_feedback`), 원문 대조 결과(`meaning_check`), 모델의 예상(`expected_effect`), 통제된 독자 평가(`reader_observation`)를 다른 칸에 둔다.
- 사용자가 이미 두 안을 읽은 적이 있으면 '읽은 순서' 칸과 `confounds` 모두에 적는다 (Q6).
- 기존 독자 지표의 `null`은 덮어쓰지 않는다.
- 반응이 들어오면 예상과 대조하고 다음 편집에 적용할 조건을 갱신한다. 이것은 기록을 활용하는 것이며 모델 가중치 재훈련이 아니다.

## 자료 규칙

- 받지 못한 자료(현재: 기존 토론 보고서 `report.md`, 기존 논문 검토 자료, 앞선 인수인계서, 대화발췌 등)는 **추측으로 채우지 않는다**. "받지 못함"으로 적는다.
- `variants.json`은 manifest의 SHA-256과 일치함까지만 확인했다. 사용자 Mac의 원본과 직접 대조한 것은 아니다 (Q14).

## 학습 기록의 원칙

- 좋아지지 않은 수정, 설명을 늦춰 이해가 어려워진 사례도 보존한다.
- "정보를 숨기면 좋아진다", "짧을수록 좋다", "은/는이 이/가보다 좋다" 같은 무조건적 규칙으로 정리하지 않는다. 적용한 문맥을 조건으로 남긴다.

## 하지 않는 것

- 원본 파일(인수인계 묶음, 이전 판 지시문, 수신 확인 보고, 기존 기록) 수정·삭제
- 필수 사실에 없는 새 사실 추가, 주장 강도 올리기
- 별도 지시 없는 편집 실험 시작, 측정 시스템 개발, 추적 코드 배포, 외부 독자 모집
- 예약 실행이나 백그라운드 작업 만들기
